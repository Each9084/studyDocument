# 第一部分 

## 一、基础知识

### 1.什么是Docker

简单来说，Docker 是一种**容器化技术**。

在没有 Docker 之前，如果你要把一个程序从你的电脑搬到服务器上，你可能需要担心：*“服务器上装了 Python 吗？”*、*“库的版本对吗？”*、*“环境变量配了吗？”*。

Docker 就像是一个**标准的集装箱**。你把代码、环境配置、依赖库全部塞进这个集装箱，然后无论这个集装箱被运到哪里（Windows, Linux, macOS），它运行起来的结果都是**一模一样的**。

**核心区别：虚拟机 vs. 容器**

- **虚拟机 (VM):** 每个虚拟机都要运行一个完整的操作系统（Guest OS），非常笨重，启动慢，占用 GB 级的内存。
- **Docker 容器:** 它们共享宿主机的操作系统内核，不需要模拟硬件。它非常轻量，秒级启动，只占用 MB 级的内存。



同时容器（Container）是一种技术概念，而 Docker 是这种技术最出名、最成功的实现工具。

- **容器（Container）** 就像是**“集装箱运输”**这个理念。它规定了货物应该怎么打包、怎么堆放。
- **Docker** 就像是**“马士基（MAERSK）”**。它是全球最大的集装箱运输公司，它提供了吊车、货轮、标准集装箱和一整套运输服务，让这个理念变成了现实并统一了标准。

> 笔者经常用这个类比来解释：虚拟机像是每个应用都住在一栋独立的房子里 (有自己的地基、水电系统)，而容器像是大家住在同一栋公寓楼里的不同房间 (共享地基和水电系统，但各自独立)。



### **2. Docker 的“三大支柱”**

要玩转 Docker，你必须掌握这三个核心概念：

1. **镜像 (Image):** 一个只读的模板。你可以把它想象成**游戏的安装包**或者 **面向对象编程里的“类”**。它包含了运行程序所需的一切。
2. **容器 (Container):** 镜像运行时的实体。它是从镜像创建的**运行实例**，可以被启动、停止、删除。它就是那个**正在运行的游戏程序**或者**“对象”**。
3. **仓库 (Registry/Docker Hub):** 存放镜像的地方。类似于 **GitHub** 或者是 **手机应用商店**。



### 3. Docker 的基本工作流

学习 Docker，其实就是在练习这个三步走战略：

- **Build（构建）:** 编写一个 `Dockerfile`，把你的应用打包成**镜像**。
- **Ship（运输）:** 将镜像上传到**仓库**（如 Docker Hub）。
- **Run（运行）:** 在任何安装了 Docker 的地方下载并运行**容器**。



### 4.微服务架构Docker

现代微服务架构几乎都依赖容器技术,Docker 让你可以：

- **隔离服务**：每个服务运行在独立容器中，互不干扰
- **独立扩展**：哪个服务负载高，就单独扩展哪个
- **独立部署**：更新一个服务不影响其他服务
- **技术多样**：不同服务可以用不同语言和框架



### 5.镜像

#### 1. 什么是镜像？（核心定义）

镜像是一个**只读（Read-only）**的轻量级、独立的软件包。它包含了运行某个软件所需的所有内容：**代码、运行时环境、库、环境变量和配置文件。**

- **直观类比：** 镜像就像是重装系统时的 **ISO 镜像文件**，或者是游戏玩家熟悉的 **Ghost 镜像**。你不能直接在 ISO 文件里玩游戏，你得先把它“安装”（运行）出来。
- **编程类比：** 镜像 = **类（Class）**；容器 = **对象（Instance）**。



镜像是一个只读的模板,而容器是一个运行实例,如果你学习过Java可能会觉得熟悉,就像Java中的类和实例的关系一样.

对应到Docker中,镜像就是一个模板,容器就是这个模板的一个实例,可以有一个,可以有多个。 







#### 2. 镜像的“洋葱结构”：分层存储

这是 Docker 最天才的设计。镜像并不是一个硬邦邦的巨大文件，而是像**洋葱**一样，由一层一层的“层（Layer）”叠起来的。

**为什么要分层？**

想象一下，如果你有 10 个镜像都是基于 Ubuntu 系统构建的，如果没有分层，你的硬盘就要存 10 份 Ubuntu。 但在 Docker 里，这 10 个镜像可以**共享**同一个 Ubuntu 基础层。这极大地节省了空间，也让下载变得飞快（如果你已经有了基础层，下载新镜像时只需下载不同的那一层）。

- **基础层 (Base Image):** 最底层通常是操作系统（如 Ubuntu, Alpine, CentOS）。
- **中间层:** 在系统之上安装的软件（如 Python, Nginx, Java）。
- **应用层:** 你的代码或特定的配置文件。

> **重点：** 镜像的所有层都是**只读**的。一旦构建完成，镜像的内容就永远不会改变。当你运行容器时，Docker 只会在这些层最上方加一个薄薄的**“可写层”**。

#### 3.镜像与操作系统的关系

我们都知道，操作系统分为 **内核** 和 **用户空间**：

对于 Linux 而言，内核启动后会挂载 `root` 文件系统来提供用户空间支持。**Docker 镜像** 本质上就是一个 `root` 文件系统。

例如，官方镜像 `ubuntu:24.04` 包含了一套完整的 Ubuntu 24.04 最小系统的 root 文件系统——但 **不包含 Linux 内核** (因为容器共享宿主机的内核)。



#### 4.镜像包含什么？

Docker 镜像是一个特殊的文件系统，包含：

内容类型

示例

**程序文件**

应用二进制文件、Python/Node 解释器

**库文件**

libc、OpenSSL、各种依赖库

**配置文件**

nginx.conf、my.cnf 等

**环境变量**

**元数据**

- ✅ 镜像是 **只读** 的
- ✅ 镜像 **不包含** 动态数据
- ✅ 镜像构建后 **内容不会改变**



#### 5.Dockerfile

如果镜像是一道菜，容器是吃这道菜的过程，那么 **Dockerfile 就是那张“菜谱”**。它是一个纯文本文件，里面记录了你构建镜像的每一项指令。

**1. 为什么要用 Dockerfile？**

你可能会问：“我直接启动一个容器，在里面装好软件，再把它保存成镜像不就行了吗？” 行是行，但那是**“黑盒操作”**。别人不知道你里面装了什么，你自己过两个月也会忘。

**Dockerfile 的好处：**

- **透明化：** 每一行命令都清晰可见。
- **版本控制：** 像代码一样存放在 Git 里。
- **自动化：** 只要有这个文件，任何人在任何地方都能构建出**完全一致**的镜像。



**2. 核心指令：Dockerfile 的“常用词汇”**

写 Dockerfile 就像是在玩乐高，你只需要掌握这几个最核心的指令：

| **指令**      | **作用**                 | **类比**                              |
| ------------- | ------------------------ | ------------------------------------- |
| **`FROM`**    | 指定基础镜像             | 选一个“底座”（比如 Ubuntu 或 Python） |
| **`WORKDIR`** | 设定工作目录             | 进屋后先去“厨房”这个房间              |
| **`COPY`**    | 将本地文件拷贝到镜像里   | 把你买的菜搬进厨房                    |
| **`RUN`**     | 在构建过程中执行命令     | 开火、洗菜、切菜（安装软件/依赖）     |
| **`EXPOSE`**  | 声明容器监听的端口       | 告诉别人这道菜在哪个桌子上领          |
| **`CMD`**     | 容器启动时默认执行的命令 | 菜上桌了，开始吃吧（运行程序）        |

为了让你有直观感受，这里有三个你以后会用到吐的命令：
